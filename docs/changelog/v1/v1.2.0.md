# DroidSock v1.2.0 Changelog

**Release Status**: Minor release

---

## Overview

v1.2.0 adds device discovery - finding ADB-capable devices on the network without already knowing an address - and closes a shell-injection gap present in every `files.*` method that shells out to the device.

---

## 🐛 Fixed

- **Shell-metacharacter injection in `files.mjs`** - every shell-based file operation (`listShell`, `stat`, `mkdir`, `remove`, `move`, `copy`, `chmod`, `diskUsage`, `find`) interpolated a caller-supplied remote path into a double-quoted shell command with no escaping, letting a path containing `$`, backticks, or an embedded `"` break out of the intended command. All nine call sites now go through a shared `utils.quoteShellArg()` helper using the standard POSIX `'\''` single-quote escaping technique. `mkdir`/`chmod`'s `mode` and `find`'s `maxDepth`/`type` are also now validated before being interpolated, closing a couple of related unvalidated-input gaps found during review.

## ✨ Added

### Device discovery (`discover.subnet` / `discover.mdns`)

`discover.subnet(cidr, port, options)` sweeps a CIDR range for a reachable TCP port - the classic fixed-address `adb connect` flow - with bounded concurrency and a `maxHosts` safety ceiling. `discover.mdns(options)` is a hand-written mDNS client (built directly from RFC 1035/6762/6763, no dependency) that queries for `_adb-tls-connect._tcp.local`-style wireless-debugging advertisements and correlates PTR/SRV/TXT/A records into `{name, host, port, txt}` entries. **EXPERIMENTAL** - both are built from the protocol specs and covered by extensive tests against real loopback TCP/UDP sockets, but neither has been run against a real device or a real multicast network yet. See [#1](https://github.com/CLDMV/droidsock/issues/1).

## 📋 Known Limitations

- `discover.subnet`/`discover.mdns`, like the rest of droidsock's protocol work, haven't been validated against real hardware or a real network yet. [#1](https://github.com/CLDMV/droidsock/issues/1) tracks the real-device session needed to validate the protocol stack they depend on.
