# DroidSock v2.1.0 Changelog

**Release Date**: October 2026
**Release Type**: Minor

---

## Overview

v2.1.0 gives a device a connection lifecycle. A dropped connection used to go unnoticed until the next call threw "Device not connected", and nothing reconnected it. Each device now emits lifecycle events, can reconnect on its own with exponential backoff, enables TCP keepalive, and can optionally probe the device with a heartbeat to catch a hung `adbd`. All of it is opt-in or additive: existing code that never passes the new options behaves as before, apart from TCP keepalive now being switched on by the `keepAlive` config value that was previously ignored.

The release also raises `engines.node` to `>=22.15.0` to match `@cldmv/slothlet` 3.22, and carries the dependency bumps queued since v2.0.3 and a development-toolchain security fix.

---

## ✨ Features

### Lifecycle events ([#75](https://github.com/CLDMV/droidsock/pull/75))

Every device emits `connecting`, `connected`, `disconnected`, `reconnecting`, `reconnected`, `error` and `gave-up`, subscribed to with `on(event, listener)`, `once(event, listener)` and `off(event, listener)` (each returns the device, so calls chain). Every payload carries `deviceId`, `host` and `port`. `disconnected` also reports whether the close was `intentional` (a `disconnect()` or `remove()` call) and a `reason` of `"requested"`, `"closed"` or `"heartbeat"`. The events honour the existing `emitEvents` config option, a throwing listener is logged without affecting the connection, and `error` is only emitted when a listener is attached.

### Opt-in auto-reconnect with backoff ([#75](https://github.com/CLDMV/droidsock/pull/75))

`device.connect(host, port, { autoReconnect })` reconnects after an unexpected drop. `true` uses the defaults; an object overrides them: `initialDelay` (default: the `retryDelay` config value, 1000 ms), `factor` (2), `maxDelay` (30000 ms), `jitter` (0.2) and `maxAttempts` (unlimited). An explicit `disconnect()` or `remove()` never triggers it, an explicit `reconnect()` cancels a pending automatic attempt, and a device that rejects authentication stops the retries with `gave-up` (reason `"auth"`). After `maxAttempts` consecutive failures the device emits `gave-up` (reason `"max-attempts"`).

### TCP keepalive ([#75](https://github.com/CLDMV/droidsock/pull/75))

The `keepAlive` and `keepAliveInterval` config values, which were defined but never read, now enable TCP keepalive on each connection socket (default on, 30 s). A silently dead link is eventually closed by the operating system and reported as a drop.

### Optional heartbeat

ADB has no ping message, so `device.connect(host, port, { heartbeat })` runs a trivial shell command on a timer (`true` means every 15 s with a 5 s timeout; an object sets `interval` and `timeout`). A probe that fails or times out closes the socket: the device emits `error`, then `disconnected` with reason `"heartbeat"`, and `autoReconnect` takes over when enabled. Probes never overlap and stop on any disconnect.

`docs/API.md` documents the options and the event table under "Lifecycle events".

## 🐛 Bug Fixes

### A failed handshake no longer leaks its socket ([#75](https://github.com/CLDMV/droidsock/pull/75))

When the handshake failed (authentication rejected, or an unexpected reply), the connection was rejected but its socket stayed open. With auto-reconnect, every failed retry would have left one behind. The socket is now destroyed on a failed handshake.

### `engines.node` now matches `@cldmv/slothlet` 3.22 ([#74](https://github.com/CLDMV/droidsock/pull/74))

`@cldmv/slothlet` 3.22 requires Node.js `>=22.15.0`, but the package declared `>=22.12.0`, so installs on Node.js 22.12 to 22.14 resolved with an engines warning for a dependency the package cannot run on. `engines.node`, the CI minimum-Node default and the README requirement are now `>=22.15.0`.

## 🔒 Security

### `brace-expansion` 5.0.9 → 5.0.12 ([#66](https://github.com/CLDMV/droidsock/pull/66))

Fixes GHSA-q2hr-2g5m-vwhr (CVE-2026-102277), a medium-severity (CVSS 5.3) denial of service: expanding input shaped like `{a},b}` takes time quadratic in the number of literal `}` characters. `brace-expansion` is a transitive dependency of `minimatch`, which only the development tooling pulls in, and the lockfile records it as development-only, so it is not part of the installed package. The repository's Dependabot alert for it ([alert 3](https://github.com/CLDMV/droidsock/security/dependabot/3)) closes once this release reaches `master`.

## Upgrade notes

- No breaking changes. Without the new options a device behaves as before; the one default-on difference is TCP keepalive, driven by the `keepAlive` config value.
- Use Node.js 22.15 or later (any Node.js 24 or 26 release qualifies). `engines.node` now says so, matching what `@cldmv/slothlet` 3.22 already required.
- To keep a long-lived device connected, pass `{ autoReconnect: true, heartbeat: true }` to `device.connect()` and listen for `reconnecting`, `reconnected` and `gave-up`.
