# DroidSock v2.2.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `release/2.2.0`

---

## Overview

v2.2.0 moves the package to the CLDMV library layout: the entries are `src/index.mjs` and `src/index.cjs`, tsup builds `dist/`, and the published package ships `dist/` and `types/` instead of root `index.mjs` / `index.cjs` files. The ADB API, its options and its behaviour are unchanged. `@cldmv/droidsock/main` still works but is now a deprecated alias of the package root.

The runtime Node.js floor is unchanged: `engines.node` stays `>=22.15.0`. Working on the repository now needs Node.js 22.22.0, declared in npm's `devEngines`; see [Requirements](#-requirements).

The release also raises `@cldmv/slothlet` to `^3.22.1` and carries the dependency and documentation updates queued since v2.1.0.

---

## ✨ Features

### CLDMV library layout ([#93](https://github.com/CLDMV/droidsock/pull/93), closes [#91](https://github.com/CLDMV/droidsock/issues/91))

- **Entry files.** The ES module entry is `src/index.mjs` and the CommonJS entry is its sibling `src/index.cjs`. `src/index.mjs` re-exports the factory from `src/droidsock.mjs` directly, as the default export and as `createDroidSock`, `DroidSock`, `ADB` and `AndroidDebugBridge`, all the same function. The package no longer imports itself by name (`@cldmv/droidsock/main`) to get there. `require("@cldmv/droidsock")` still returns the factory with the same named aliases as properties.
- **Build.** tsup replaces `build.mjs`. `dist/` mirrors `src/` file by file, because slothlet scans `dist/api/` at runtime, and `dist/index.cjs` is a verbatim copy of `src/index.cjs`. Source maps are built but not published. `prepack` runs the build, so a packed or published tarball always carries a fresh `dist/`.
- **Types.** Declarations come from `types/src/`, and `@cldmv/droidsock/main` now has the same types as the root.
- `./package.json` is exported.

### `@cldmv/droidsock/main` is a deprecated alias ([#93](https://github.com/CLDMV/droidsock/pull/93))

`@cldmv/droidsock/main` used to point straight at `droidsock.mjs`, which only had a default export. It now re-exports the package root, so it has the same default and named exports, and importing it prints a `DeprecationWarning` once per process with code `CLDMV_DROIDSOCK_MAIN` (`console.warn` where there is no `process`). `node --no-deprecation` silences it. The alias is removed in the next major version; import `@cldmv/droidsock` instead.

### `droidsock-dev` export condition on the root ([#93](https://github.com/CLDMV/droidsock/pull/93))

The `droidsock-dev` condition, which before only covered `./main`, now sits on `.` too, for `import`, `require` and `types`. In a checkout the package resolves to the built `dist/` by default and to `src/` under `--conditions=droidsock-dev`. The Vitest suite and the examples in the README run with it. Installed copies never see the condition.

## 📦 Requirements

### Runtime floor unchanged, development floor in `devEngines` ([#93](https://github.com/CLDMV/droidsock/pull/93), [#100](https://github.com/CLDMV/droidsock/pull/100))

- **Runtime:** `engines.node` stays `>=22.15.0`, the floor `@cldmv/slothlet` sets, for `import` and `require()` alike. Every Node.js version in that range has `require(esm)`. On a Node.js without it, the CommonJS entry's error now asks for `>=22.15.0` (v2.1.0's message said `^20.19.0 or >=22.12.0`).
- **Development:** working on this repository needs Node.js 22.22.0 or later, because the development toolchain (tsup 9 among others) doesn't run on earlier 22.x releases. That floor is declared in `devEngines.runtime` with `onFail: "error"`, so it doesn't affect anyone installing the package.

## 🐛 Bug Fixes

### Development check removed ([#92](https://github.com/CLDMV/droidsock/pull/92))

The root `devcheck.mjs`, which the entry tried to load in a source checkout, is gone. It was never published, so installed copies are unaffected. The `droidsock-dev` condition already chooses `src/` or `dist/` in a checkout.

### `@cldmv/slothlet` `^3.22.1` ([#93](https://github.com/CLDMV/droidsock/pull/93))

The entry now imports the factory, and with it `@cldmv/slothlet`, statically. slothlet 3.22.0 has a top-level await in its module graph, which makes `require()` of the package fail with `ERR_REQUIRE_ASYNC_MODULE`; 3.22.1 doesn't. The dependency range moves from `^3.15.0` to `^3.22.1`, and the lockfile from 3.22.0 to 3.22.1.

The lockfile stays on 3.22.1 rather than 3.23: with 3.23.0 the device tests hang and `devices.get()` returns a different object after a disconnect ([slothlet#688](https://github.com/CLDMV/slothlet/issues/688)). The `^3.22.1` range still allows 3.23 in a consumer's install.

### The `./main` deprecation warning survives bundling ([#99](https://github.com/CLDMV/droidsock/pull/99), fixes [#98](https://github.com/CLDMV/droidsock/issues/98))

`package.json` declared `"sideEffects": false`, which lets a bundler drop the top-level code in `main.mjs` that prints the deprecation warning. `sideEffects` now lists `./src/main.mjs` and `./dist/main.mjs`, as uuid and holdmytask do.

## 🔧 CI & tooling

- `build:ci` runs `lint`, `format:check`, `types:build` and the tsup `build`; the coverage jobs run it before measuring (`coverage_build_command`), and the bundle-size check measures `dist/` ([#93](https://github.com/CLDMV/droidsock/pull/93)).
- `test:cjs` builds first and checks `dist/` with `node --test`. New tests cover the `./main` alias and `src/index.cjs` ([#93](https://github.com/CLDMV/droidsock/pull/93)).
- The CI and publish workflows' `min_node_version` default is 22.22.0 (was 22.15.0 in CI and 22.12.0 in publish), the dev toolchain floor; its description and a comment say it should match `devEngines`, not `engines`. Node.js 22.15 through 22.21 are still supported at runtime but no longer in the test matrix ([#93](https://github.com/CLDMV/droidsock/pull/93), [#100](https://github.com/CLDMV/droidsock/pull/100)).
- The stray root `test.txt` and an empty `screenshot.png` are gone; neither was published ([#93](https://github.com/CLDMV/droidsock/pull/93)).

## Upgrade notes

- The runtime Node.js floor is unchanged at 22.15.0.
- Replace `@cldmv/droidsock/main` with `@cldmv/droidsock`. It still works in 2.x but prints a `DeprecationWarning` (code `CLDMV_DROIDSOCK_MAIN`) and goes away in the next major version.
- The ADB API is unchanged. Two small differences in the entry: importing the package now loads `@cldmv/slothlet` at import time instead of on the first call (the api modules are still composed when the factory runs), and the default export is the factory itself, so its `name` is `createDroidSock` rather than `droidsock`.
- Code that reached into the package's file layout (the root `index.mjs` / `index.cjs`, `types/dist/`, `types/index.d.mts`) outside the exports map has to move to the exported paths.
