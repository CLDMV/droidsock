# DroidSock v2.2.1 Changelog

**Release Date**: November 2026
**Release Type**: Patch
**Branch**: `release/2.2.1`

---

## Overview

v2.2.1 keeps `@cldmv/slothlet` below 3.24.0. slothlet 3.24.0 hands sockets back to droidsock as proxies, so `device.connect()` throws `TypeError: Illegal invocation` on every install that resolves it. The `^3.22.1` range in v2.2.0 allowed 3.24.0, so a fresh install of v2.2.0 picks it up today; v2.2.1 narrows the range to `>=3.22.1 <3.24.0`.

No droidsock code changed. The rest of the release is test and CI work: the Vitest suite now also runs against the built `dist/`, and the dev export condition actually reaches the test workers.

---

## 🐛 Bug Fixes

### `@cldmv/slothlet` capped below 3.24.0 ([#112](https://github.com/CLDMV/droidsock/pull/112))

From 3.24.0, slothlet hands out a proxy for a `net.Socket` (or any `node:stream` object) that a module returns, and native calls on it fail with `TypeError: Illegal invocation` ([slothlet#708](https://github.com/CLDMV/slothlet/issues/708)). droidsock's connection module creates the socket and the device module calls `socket.setKeepAlive()` on it, so every `device.connect()` threw. 3.23.0 is not affected.

The dependency range moves from `^3.22.1` to `>=3.22.1 <3.24.0`. The lockfile stays on 3.22.1. No fixed 3.24.x is planned, because slothlet's next release is 4.0.0; moving to slothlet 4 is separate work.

Packages that depend on droidsock and pinned slothlet with an npm `overrides` entry to work around this can drop the override once they require `@cldmv/droidsock` `^2.2.1`.

## 🧪 Tests

- The Vitest config sets the `droidsock-dev` condition with `devCondition()` from `@cldmv/configs` 1.4.0. The old `test.nodeOptions` setting isn't a Vitest option, so the condition never reached the test workers ([#103](https://github.com/CLDMV/droidsock/pull/103)).
- `npm run test:dist` builds `dist/` and runs the Vitest suite against it. `npm test` and `ci:coverage` include it ([#107](https://github.com/CLDMV/droidsock/pull/107)).
- The device tests compare leaves by `host:port` instead of object identity, and the shell-control tests check that `stop()` reaches the real control. From slothlet 3.23, `devices.get()` and `devices.list()` return each module's own view of the same leaf, so identity checks failed although the device was the same ([#106](https://github.com/CLDMV/droidsock/pull/106)).

## 🔧 CI & tooling

- New `sync-release-notes.yml` companion workflow from the v4 template, unchanged. It keeps GitHub Release bodies in step with the per-version changelog files and creates missing version tags ([#110](https://github.com/CLDMV/droidsock/pull/110)).

## Upgrade notes

- Drop-in for v2.2.0; the API and runtime code are unchanged.
- If your install resolved `@cldmv/slothlet` 3.24.0 under v2.2.0, updating to v2.2.1 moves it back to 3.23.x or 3.22.x and `device.connect()` works again.
