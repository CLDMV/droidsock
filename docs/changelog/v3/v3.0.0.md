# DroidSock v3.0.0 Changelog

**Release Date**: November 2026
**Release Type**: Major
**Branch**: `release/3.0.0`

---

## Overview

v3.0.0 switches the CommonJS entry to the generic `index.cjs` shim used across the CLDMV libraries. `require("@cldmv/droidsock")` still returns the `createDroidSock` function, so `require(x)(...)` works as before, but it no longer carries the `createDroidSock`, `DroidSock`, `ADB` and `AndroidDebugBridge` alias properties the hand-written entry attached to it.

This is the only breaking change, and it only affects code that uses `require()` and reads one of those four properties off the result. ESM `import` is unchanged, and so is every method on the device object.

---

## 💥 Breaking Changes

### `require("@cldmv/droidsock")` no longer has alias properties ([#118](https://github.com/CLDMV/droidsock/pull/118), fixes [#117](https://github.com/CLDMV/droidsock/issues/117))

The ESM entry exports one distinct value, the `createDroidSock` function, under five names (`default`, `createDroidSock`, `DroidSock`, `ADB` and `AndroidDebugBridge`). The shim sees a single value and hands back that function itself, with nothing attached:

```javascript
const droidsock = require("@cldmv/droidsock");
// => the createDroidSock function; Object.keys(droidsock) is []

const api = await droidsock();
```

Before, the entry did `module.exports = droidsock` and then attached `createDroidSock`, `DroidSock`, `ADB` and `AndroidDebugBridge` to it as properties.

- `require(x).createDroidSock(...)`, `require(x).DroidSock(...)`, `require(x).ADB(...)` and `require(x).AndroidDebugBridge(...)` now throw, because those properties are `undefined`. Call `require(x)(...)` directly.
- `const { ADB } = require(x)` and similar destructuring now gives `undefined`. Rename the binding instead (`const ADB = require(x)`), or use `import { ADB } from "@cldmv/droidsock"`.
- `require(x)(...)` keeps working, and so does every ESM named export.
- Nothing new is exposed: `require(x).default` is `undefined`, as it was before.

`src/index.cjs` is now the same small file as in other CLDMV libraries (Node version guard, then `require("./index.mjs")`), and the build still copies it unchanged to `dist/index.cjs`. The CJS tests expect the bare function and check that none of the alias names are present on it, against both `src/` and `dist/`.

## 🔧 CI & tooling

- `ci.yml` adopts the CLDMV/.github v4.46.0 concurrency block, so superseded runs on `next`, `hotfixes` and the release PRs are cancelled instead of filling the org's hosted runner pool ([#119](https://github.com/CLDMV/droidsock/pull/119), fixes [#116](https://github.com/CLDMV/droidsock/issues/116)).
- `ci.yml` is synced with the v4.43.0 template, so the release PR stops rerunning the matrix on a commit its push run already tested ([#114](https://github.com/CLDMV/droidsock/pull/114)).

## Upgrade notes

- `require("@cldmv/droidsock")` is the `createDroidSock` function with no properties. Call it directly: `require(x)(...)`.
- Replace `require(x).createDroidSock`, `.DroidSock`, `.ADB` and `.AndroidDebugBridge` with `require(x)`, or switch to `import { ADB } from "@cldmv/droidsock"`.
- ESM `import` is unchanged.
